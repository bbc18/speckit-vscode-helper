## 2026-06-03 - [CRITICAL] Prevent Command Injection in Git Worktree Service
**Vulnerability:** The project used `child_process.exec` (via the `ExecFn` type wrapper) to execute raw git command strings (e.g., `git worktree add "${targetPath}" "${branch}"`). This is highly susceptible to command injection if `targetPath` or `branch` containing shell meta-characters are supplied by a malicious actor.
**Learning:** For git interactions, executing parameterized command arrays using `child_process.execFile` prevents the shell from interpreting embedded variables as separate shell commands. Also learned that `git rev-parse --verify` treats `--` as indicating file paths, so `--` must not be used when verifying branches. Conversely, `git worktree add` can and should use `--` to delimit user-provided target paths safely.
**Prevention:** Always use `child_process.execFile` with an array of arguments, instead of `child_process.exec`. Include the `--` separator before user-controlled positional arguments where supported, except for git commands like `rev-parse --verify` that have a specialized treatment for it.
