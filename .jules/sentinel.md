## 2026-06-18 - Prevent Command Injection in Git Execution
**Vulnerability:** The project used `childProcess.exec` to run Git commands. Passing user-controlled branch names directly into the command string (e.g., in `addWorktree`) exposed the application to command injection vulnerabilities.
**Learning:** `childProcess.execFile` with an explicitly separated executable and argument array is necessary for securely running shell commands in TypeScript/Node.js to prevent injection. Additionally, adding `--` before positional arguments in `git worktree add` is crucial to prevent argument injection. However, a specific quirk in Git causes `git rev-parse --verify -- <branch>` to fail because Git interprets it as a file path.
**Prevention:** Always define execution abstractions (`ExecFn`) to explicitly enforce `childProcess.execFile` signatures (requiring `file: string` and `args: ReadonlyArray<string>`). Consistently use `--` to delimit user input in Git commands, *except* where explicitly incompatible like `rev-parse --verify`.
