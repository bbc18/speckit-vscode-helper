## 2024-05-20 - Prevent Command Injection via execFile
**Vulnerability:** The codebase was wrapping `child_process.exec` in a custom `ExecFn` typed to execute a command string, allowing user-controlled inputs (like branch names and paths) in `git worktree add` commands to be evaluated by the shell, leading to Command Injection risks.
**Learning:** `childProcess.exec` passes strings to the system shell for evaluation. If input paths or branch names contain shell metacharacters or spaces, they can escape the intended git command string. Even wrapping with double quotes is insufficient to prevent all forms of injection.
**Prevention:** Always use `childProcess.execFile` and pass arguments as an explicit array of strings to bypass shell evaluation entirely. When passing variable length/content paths or branch names to git commands like `worktree add`, include the `--` separator before positional path arguments to prevent them from being interpreted as malicious command line options.
