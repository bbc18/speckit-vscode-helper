## 2026-06-26 - [Command Injection via child_process.exec]
**Vulnerability:** Found `child_process.exec` used with user-controlled input (branch names and target paths) to execute git commands in `worktreeService.ts` and `worktreeAggregator.ts`, which could allow arbitrary command execution. Additionally, using `rev-parse --verify ${branch}` allowed arguments to be interpreted as files if `--` was used incorrectly.
**Learning:** `child_process.exec` passes the command string to a shell, making it susceptible to injection. When executing git commands, `child_process.execFile` should be used with an explicit array of arguments to separate the executable from its arguments. For `git rev-parse --verify`, avoiding the `--` separator before the branch name is crucial because it instructs Git to treat the argument as a file path instead of a branch/revision. For `git worktree add`, `--` should be used before positional path arguments.
**Prevention:** Always use `childProcess.execFile` with an array of arguments instead of `childProcess.exec` when running git commands. Include the `--` separator before user-controlled positional arguments (like paths) to prevent argument injection, except for specific subcommands where it breaks functionality (like `git rev-parse --verify`).
