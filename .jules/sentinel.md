## 2024-03-20 - Command Injection Prevention in Git Executions
**Vulnerability:** The codebase was previously using `childProcess.exec` to run Git commands directly against string templates (e.g., ``git worktree add "${targetPath}" "${branch}"``). This allowed for command injection via shell execution if worktree paths or branch names could contain unsanitized input or shell control characters.
**Learning:** Security depends heavily on bypassing the system shell entirely when interpolating arguments into a command string. Even seemingly safe variables can act as argument or command injection vectors if the shell parses them.
**Prevention:** Instead of string formatting, strictly type wrapper execution functions (like `ExecFn`) to expect separate executable names and argument arrays (`file: string`, `args: ReadonlyArray<string>`). Always use `childProcess.execFile` in Node.js when executing user-influenced paths. Make use of the `--` standard convention to delineate between options and positional arguments to completely neutralize argument injection inside `execFile`.
