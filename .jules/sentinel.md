## 2024-03-20 - [Command Injection via `childProcess.exec` in Git Worktree Service]
**Vulnerability:** The Git Worktree service (`src/services/worktreeService.ts`) was using `childProcess.exec` to execute `git worktree add`, string-interpolating user-supplied input (feature branch names) directly into the command string. Since branch names were derived from the filesystem which could be modified by users (or an attacker writing branch-like filenames to exploit the extension), this opened the extension up to arbitrary Command Injection.
**Learning:** `childProcess.exec` spawns a shell and evaluates the entire string, parsing meta-characters (like `;`, `|`, `&&`, `$()`). Even seemingly safe operations on local tools like `git` become remote execution paths if the tool input is untrusted and directly concatenated.
**Prevention:** Always use `childProcess.execFile` instead of `childProcess.exec`. `execFile` executes the binary directly without spawning a shell, passing arguments as a strictly defined array. For user-controlled positional arguments (such as paths or filenames), always use the `--` separator (`git`, `['worktree', 'add', '--', targetPath, branch]`) to explicitly separate commands from arguments, preventing Argument Injection.
## 2025-02-24 - [CRITICAL] Git Command Injection via child_process.exec
**Vulnerability:** Git operations were being executed using `child_process.exec` where the executable and user inputs were directly concatenated into a single shell command string. For instance, executing `git worktree add -b "${branch}" "${targetPath}"` allowed arbitrary shell commands inside `${branch}` or `${targetPath}` to be evaluated by the underlying shell, leading to command injection and potential RCE.
**Learning:** `child_process.exec` passes the entire command string to a shell instance (e.g. `/bin/sh -c`). When using variables sourced from filenames, environment metadata, or user inputs, executing commands with `exec` creates a critical vulnerability. Additionally, when switching to an arguments array format (for `execFile`), special care must be taken with git operations that verify values (e.g., `git rev-parse --verify`). Using the arguments array separator `--` inside `git rev-parse --verify` actually causes git to treat the input as a file path rather than a reference, unexpectedly causing validations to fail.
**Prevention:** Avoid `child_process.exec` completely for commands acting on input. Use `child_process.execFile` instead, which strictly separates the executable (`file: string`) from the variables (`args: readonly string[]`). To prevent git from parsing arguments as options (argument injection), insert a `--` separator immediately before the variable inputs inside the args array (`['worktree', 'add', '--', targetPath, branch]`), except when specifically avoiding it due to how git commands uniquely interpret `--` (e.g. `git rev-parse --verify`).
## 2025-02-25 - [HIGH] Git Argument Injection in `git rev-parse --verify`
**Vulnerability:** Even though Git execution was safely migrated to `child_process.execFile` with an array of arguments, a gap remained for user-controlled positional arguments. In the `git rev-parse --verify` command inside `addWorktree`, we cannot safely use the `--` separator to signify the end of options because Git interprets `--` in this specific context as "treat what follows as a file path, not a branch reference," causing the validation to fail. Since user-supplied branch names were not validated, an attacker could supply a branch name starting with a hyphen (e.g., `-v`), leading to Argument Injection where Git treats the branch name as a command-line flag rather than a branch.
**Learning:** Argument Injection can happen even when using `execFile` if a tool misinterprets untrusted input as a flag instead of a positional argument. The standard mitigation of using the `--` separator is sometimes inapplicable due to tool-specific idiosyncrasies (like with `git rev-parse --verify`). In such cases, strict input validation must be enforced.
**Prevention:** Always validate that user-supplied input intended for command-line arguments does not begin with a hyphen (`-`) if the `--` separator cannot be used to isolate positional arguments. Ensure strict checks are present at the entry point of the executing function.
