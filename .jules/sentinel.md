## 2026-06-07 - Command Injection via child_process.exec wrapper
**Vulnerability:** A project-specific `ExecFn` type wrapped `child_process.exec` and passed unsanitized arguments directly into shell commands via string interpolation (e.g. `git rev-parse --verify "${branch}"`). This allowed command injection if user-controlled strings, such as `branch` or `targetPath`, contained shell metacharacters.
**Learning:** `child_process.exec` passes strings to a shell, inviting injection vulnerabilities. Creating generic wrapper functions (`ExecFn`, `makeExecGit`) that inherit `exec`'s signature effectively obscures this vulnerability and propagates it across multiple services (like `worktreeService.ts` and `worktreeAggregator.ts`).
**Prevention:** Always use `child_process.execFile` when executing git commands. Define `ExecFn` wrappers strictly to accept `file: string` and `args: string[]` to separate the executable from user-supplied arguments. In Git commands specifically, utilize the `--` separator before positional file path or branch arguments (e.g. `['worktree', 'add', '--', targetPath, branch]`) to prevent argument injection.
