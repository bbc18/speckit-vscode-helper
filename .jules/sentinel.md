## 2025-02-18 - Prevent Command Injection with execFile
**Vulnerability:** Command injection was possible in Git command execution because `child_process.exec` was used with string concatenation (e.g., `git worktree add "${targetPath}" "${branch}"`).
**Learning:** `child_process.exec` passes the entire command string to a shell, making it vulnerable to injection if any of the concatenated strings (like branch names) contain shell metacharacters. Even using quotes is insufficient if the user-controlled input can escape them.
**Prevention:** Always use `child_process.execFile` and pass arguments as an array instead of a single string. Additionally, for Git commands, use the `--` separator before user-controlled positional arguments (e.g., `git worktree add -- <path> <branch>`) to explicitly distinguish between flags and arguments, preventing malicious flags from being injected. However, be careful not to use `--` when the argument is meant to be parsed as a revision (e.g., `git rev-parse --verify`).
