## 2024-05-24 - [CRITICAL] Prevent Command Injection in Git Exec Wrappers
**Vulnerability:** The custom `ExecFn` type and `makeExecGit` wrapper originally accepted a single `cmd: string` which was passed directly to `childProcess.exec`. This allowed shell interpretation of untrusted input (like worktree paths and branch names) in Git commands, leading to critical command injection vulnerabilities.
**Learning:** Security mechanisms abstracting command execution in TypeScript/Node.js must separate the executable from its arguments to prevent shell expansion. The use of `childProcess.exec` is inherently dangerous when any part of the command string is user-controlled or dynamically generated.
**Prevention:** Replaced `childProcess.exec` with `childProcess.execFile`. Refactored `ExecFn` to `(file: string, args: readonly string[], opts, cb) => void` and passed arguments explicitly in an array. Utilized the `--` separator where appropriate in Git commands to ensure arbitrary paths/branches are not interpreted as command options.
