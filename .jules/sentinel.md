## 2026-06-30 - [Command Injection via childProcess.exec]
**Vulnerability:** The `WorktreeService` (and its consumer `WorktreeAggregator`) utilized `childProcess.exec` to execute arbitrary Git commands, combining an executable name ('git') with potentially user-controlled inputs (like branch names and target paths). This exposed the application to command injection, as `child_process.exec` passes the string to a shell, allowing attackers to chain commands with shell metacharacters. In addition, Git parameters were provided without preventing them from being interpreted as options if they started with a dash.
**Learning:** `childProcess.exec` is dangerous when handling variable input as it evaluates commands inside a shell environment. Additionally, when arguments contain branch or file names, it is essential to ensure they aren't parsed as unexpected arguments to the underlying binary (e.g. `--branch`). One caveat discovered is that using the `--` separator with `git rev-parse --verify` will make Git treat the argument as a file, causing unexpected failures; the separator is safe for other git commands such as `git worktree add`.
**Prevention:** Avoid `child_process.exec` when incorporating dynamic inputs; instead, use `child_process.execFile` or `child_process.spawn`. These functions pass the program arguments explicitly as an array instead of as a formatted string to a shell. Furthermore, utilize the `--` argument separator in Git commands (except when it conflicts with the command's expected positional syntax, as with `rev-parse --verify`) to signal the end of command options.
