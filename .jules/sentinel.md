## 2026-06-25 - Prevent Command Injection in Git Execution
**Vulnerability:** Found a command injection vulnerability in `src/services/worktreeService.ts` where `childProcess.exec` was used with a concatenated shell string for git commands, such as `git worktree add -b "${branch}" "${targetPath}"`. If variables like `${branch}` contained shell metacharacters, it could result in arbitrary code execution.
**Learning:** `childProcess.exec` passes the entire string to a shell, making it susceptible to injection attacks when handling user-provided strings. `childProcess.execFile` separates the executable from its arguments, treating arguments literally and bypassing the shell, fundamentally preventing command injection.
**Prevention:** Always use `childProcess.execFile` instead of `childProcess.exec` when building OS commands dynamically. Pass the executable name and an array of arguments, using the `--` separator before positional arguments to prevent argument injection if the command allows it (but note `git rev-parse --verify` fails if using `--`).
