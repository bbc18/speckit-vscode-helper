## 2024-05-31 - [Command Injection via `childProcess.exec` in Git Commands]
**Vulnerability:** The application uses `childProcess.exec` directly to run Git commands (e.g., `git worktree list --porcelain`, `git worktree add -b "branch" "target"`). `childProcess.exec` invokes a shell, making it susceptible to command injection if `branch` or `targetPath` contain unescaped shell metacharacters (e.g., `;`, `&`, `|`, `$()`). Even though `execGit` attempts to wrap quotes, quotes in strings can break out.
**Learning:** Shell execution (`childProcess.exec`) is inherently risky when dealing with user-controlled input, including repository branches and paths.
**Prevention:** Use `childProcess.execFile` instead of `exec`, passing arguments as an array rather than constructing a single string. This prevents the shell from interpreting metacharacters. If paths/branches might start with `-`, use `--` to delimit options from positional arguments (except where Git specifically doesn't support it, like `git rev-parse --verify`).
